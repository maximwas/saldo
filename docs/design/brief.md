# Saldo: дизайн-бриф для Figma

Специфікація: `docs/spec/specification-v1.1.txt` (посилання нижче — §розділи). Токени для коду: `docs/design/theme.css`.
Демо-дані: `docs/design/demo-data.md` (вигадані).

## Продукт
Особистий фінансовий застосунок одного користувача, Україна, інтерфейс українською. Desktop, tablet, mobile, PWA.
Головна робота: знати, скільки можна витратити до наступного доходу, що й коли платити, і бачити план окремо від факту.
Інваріанти (§1): один факт вводиться один раз; план окремо від факту; календар не підтверджує оплату; переказ і резерв
не є витратою; невідоме не вигадується; кожен підсумок має пояснювані складові.

## Напрям
Спокійний сучасний фінтех: холодно-сірий фон застосунку (`app`), на ньому білі картки (`card`, radius 20, м'яка тінь
`shadow/card`), один насичений синій `primary` #2B66F6 для дій і головної картки «Доступно». Шрифт Fixel (MacPaw):
Fixel Display для заголовків і сум, Fixel Text для інтерфейсу; цифри табличні.
**Що робить його зрозумілим:** кожен блок — окрема картка з чітким заголовком і посиланням-дією праворуч («Усі
платежі ›»); головне число — одне, велике, на синій картці, а поруч розкладено, з чого воно складається; суми завжди
праворуч і вирівняні; колір лише там, де він щось означає (статус, категорія, резерв), решта — відтінки сірого тексту.
Іконки категорій — кольорова іконка в м'якому колі того ж кольору; сервіси — їхні логотипи.
**Уникати:** кольорових фонів карток без змісту; червоного для будь-чого, крім нестачі; CAPS-підписів і eyebrow;
градієнтів-декору; емодзі; «→» у кнопках; тіней на всьому підряд (картка — `shadow/card`, плаваюче — `shadow/float`);
сирих значень замість токенів.

## Граматика сум (всюди однаково)
Компоненти **Amount** (Kind × Size S 16 / M 22 / L 28 / XL 44) і **StatusPill** (Kind).
| Що | Як |
|---|---|
| Факт | Amount Kind=Fact: `text-primary` |
| План | Amount Kind=Plan: приглушена `text-secondary`; поруч StatusPill Plan — контурна пігулка «План» (рамка `border-strong`) |
| Невідома сума | Amount Kind=Unknown «? ₴» (text-tertiary) + StatusPill «Сума невідома» — ніколи 0 |
| Дата минула без підтвердження | StatusPill Unconfirmed «Не підтверджено» — оранжевий (`warning-soft` / `warning-text`); ніколи «прострочено» й ніколи червоний |
| Нестача, дефіцит, мінус місяця | Amount Shortfall і StatusPill Shortfall «Не вистачає» — `negative`; єдине місце червоного |
| Резерв | Amount Reserve і StatusPill Reserve — фіолетовий `reserve` |
| Переказ | Amount Transfer — нейтральний `text-tertiary`; не червоний, не зелений, не в витратах |
| Дохід | Amount Income: «+» і `positive-text` |
| Оплачено / частково | StatusPill Paid (зелена) / Partial (синя) |
| Оцінка (податок) | StatusPill Estimate «Оцінка» — сіра `subtle` |
| Утримано джерелом | StatusPill Withheld «Утримано», окремо від «Оплачено» |
Формат: `1 583,25 ₴` — пробіл тисяч, кома, валюта після числа; від'ємне — справжній мінус «−». Валюти: ₴, $, €.

## Файл Figma
- Файл **Saldo** — у кожному виклику Pixelwright передавай `file: "Saldo"`.
- Тариф Starter: 3 сторінки, 1 режим у колекції. Сторінки: **Design System** (0:1), **Screens** (1:104), **Dark** (1:105).
- На Design System: **Service logos** (1:167, x 0, y 0): компоненти `Logo/<id>` 64×64 — не чіпати й не рухати;
  **Components** (Section 2:9202, x 2700); **Forms & overlays** (x 2700, y 2500); **Data & navigation** (x 8500, y 0);
  **Foundations** (x 0, y 3200) — кольори, текст, spacing, radius, тіні, граматика сум.
- Змінні (design_read пише їх як WEB code syntax, той самий у `theme.css`):
  - **Color**: `--color-app, card, raised, subtle, border, border-strong`; `--color-text-primary, text-secondary,
    text-tertiary, neutral, on-primary`; `--color-primary, primary-hover, primary-soft, primary-text`;
    `--color-positive|negative|warning|reserve` з `-soft` і `-text`; `--color-cat-<blue|green|orange|pink|purple|
    teal|yellow|red|cyan|lime>` з `-soft` і `-text`.
  - **Color Dark** — ті самі імена, темні значення; темних екранів немає, тема перемикається токенами в коді. WEB code syntax у Color Dark — `var(--dark-…)`, щоб design_apply не плутав колекції; у коді темні значення мають ті самі імена `--color-…` під `[data-theme="dark"]`.
  - **Space**: `--spacing-0, 0_5, 1, 1_5, 2, 2_5, 3, 4, 5, 6, 8, 10, 12, 16` (0…64 px, крок 4 + 2, 6, 10).
  - **Radius**: `--radius-xs` 6, `sm` 8, `logo-md` 10, `md` 12 (контроли), `inner` 14, `card` 20, `full` 999.
- Текстові стилі: display/hero (Fixel Display SemiBold 44/52, −1px), display/page-title (30/38, −0,5px),
  display/number (28/36, −0,5px), display/number-sm (22/28, −0,3px); text/card-title (Text SemiBold 18/26);
  text/body, body-medium, body-semibold (16/24); text/label, label-medium, label-semibold (14/20);
  text/caption, caption-medium (13/18); text/micro (Medium 12/16).
- Ефекти: **shadow/card** (картки), **shadow/float** (FAB, діалог, шторка, тост, меню).
- Іконки: Lucide (у коді lucide-react), компоненти `Icon/<lucide-name>` (Icons 1:1536); бракує — `icons_insert` і
  компонент `Icon/<name>` там само. 20 px у навігації, 24 у таббарі, 16–18 у кнопках і рядках.

**Бюджет (§11), Цілі й конверти та великі витрати (§12), Авто (§13), Податки (§14–17)** — профіль не налаштовано:
порожній стан і приклад налаштованого профілю з позначкою «приклад»; картка зобов'язання (база з операціями, версія
правила, нараховано/утримано/сплачено/залишок, резерв, стани); **Статистика (§20)** — кожна діаграма з табличним
еквівалентом; **Налаштування (§21)**; **Сповіщення** (центр); **Стани**: вхід, офлайн, очікує синхронізації, конфлікт,
порожні списки.
**Спільний доступ (ADR 19, рішення Максима 30.10.2026).** Демо: простори «Мій Saldo» (owner) і «Сімейний»
(editor); друга людина — ініціал «О».
- *Перемикач простору:* desktop — над меню в Sidebar (назва, роль-бейдж «Власник / Редагує / Переглядає», список
  просторів з галочкою); mobile — назва простору в Topbar з шевроном, відкриває шторку зі списком. Без другого
  простору перемикач — просто назва.
- *Налаштування → «Доступ»:* учасники (аватар-ініціал, ім'я, email, роль select), «Відкликати» з підтвердженням;
  «Запросити»: email + роль → посилання з «Копіювати» і строком «дійсне 7 днів»; список запрошень, що очікують
  («Скасувати»); «Вийти з простору» для не-власника; viewer бачить список лише для читання.
- *Прийняття запрошення* (`/invite/…`, без оболонки, як екран входу): «Олена запрошує вас у простір „…“ з роллю
  Редагує», email; кнопки «Прийняти» / «Увійти іншим акаунтом»; новий акаунт — поле пароля; стани «Посилання
  прострочене», «Вже прийнято», «Запрошення на іншу адресу».
- *Автор операції:* малий ініціал-аватар у рядку таблиці й картці операції / платежу, підказка «Вніс(ла): …».
- *«Підтвердив(ла)»:* в оплаченому зобов'язанні — «Підтвердив(ла) Олена · 29.10, 18:40»; конфлікт «Цю оплату вже
  підтвердила Олена» з діями «Відкинути мою операцію» / «Лишити як окрему витрату».
- *Фільтр «Хто»:* чип у фільтрах операцій (усі / я / учасник), лише коли в просторі більше одного учасника.
- viewer: кнопки запису (FAB, «Додати», «Оплачено») приховані, бейдж «Лише перегляд» у Topbar.

  окремі фрейми «<Екран> · <Стан> / Desktop|Mobile» у своїй Section:
  - видалення: Dialog (desktop) або BottomSheet (mobile) з наслідками, Danger-кнопка, потім Toast «Видалено» і
    «Скасувати»; якщо видалити не можна — архів;
  - редагування: заповнена форма і помилки валідації;
  - порожній стан (EmptyState з дією) і завантаження (skeleton);
  - помилка збереження й офлайн («Очікує синхронізації»);
  - роль «Лише перегляд»: дії приховані або вимкнені;
  - підтвердження з домену екрана: скасувати оплату, відкликати доступ, вийти з простору, закрити борг тощо.
  Ключові стани — desktop і mobile, решту — на одній платформі.
- Перевірка кожного екрана: screenshot desktop і mobile (масштаб 0.5 цілим, 1–2 для деталей); суми праворуч
  вирівняні, нічого не обрізано, mobile без горизонтального скролу, цілі ≥44, граматика сум дотримана.

## Правила роботи в Pixelwright
- Перед першим записом прочитай `guide` topics workflow, write, layout, tokens.
- Більшість роботи — XML через `design_apply`: фрейми, auto layout, тексти, інстанси, заливки, прив'язки до змінних.
  `execute` — лише для того, чого `design_apply` не вміє (component set і варіанти, component properties, складні
  override); не більше 1 execute на 5 design_apply. У звіті вкажи обидві кількості, а для кожного execute — причину
  (Максим, 30.10.2026, для всіх Figma-агентів).
- Кожен колір — змінна, кожен gap/padding — space, radius — змінна, текст — текстовий стиль. Сирих hex немає.
  В кінці своєї ділянки — `design_lint`, потім `tokens_bind` для сирих значень.
- Auto layout скрізь. Імена шарів англійською. Екрани з інстансів компонентів, а не з копій.
- Після кожного компонента чи екрана — `screenshot` (масштаб 1–2 для деталей): перекриття, обрізання, вирівнювання.
- Не видаляй і не рухай того, чого не створював (Service logos, ділянки інших агентів). Працюй у своїх координатах.
- Субагентів не запускай. Файли репозиторію не змінюй, якщо твій бриф не каже інакше.
